# RE:年モノ

**「去年の今ごろ動いていた仕事」を、今年もそろそろ思い出させるためのMVPです。**

Google Drive Activity API の編集アクティビティを使い、担当者個人の閲覧履歴ではなく **ファイルIDを主語** にして、季節性のある業務ファイルを再発見します。

## MVPでやること

実行日を基準に、次の条件を満たすファイルを候補として抽出します。

- 昨年の同日を中心に **±21日** の期間を見る
- その期間に **2日以上** 編集されている、または EDIT activity が **3件以上** ある
- 直近 **90日** は編集されていない
- 担当者ではなくファイルID単位で集計する
- 結果を Google スプレッドシートへランキング表示する

出力スプレッドシートは、指定済みの Google Drive フォルダ **「RE:年モノ」** に自動作成します。

## いちばん重要な検証

Drive Activity API は過去のアクティビティを問い合わせられますが、Google は長期の保持期間を明示保証していません。

そのため、MVPの最初の目的は次の一点です。

> **実際の職場環境で、約1年前の EDIT activity を十分に取得できるか。**

`diagnoseHistory()` を実行すると、約1年前の期間について取得できたファイル数と activity 数をログに出します。

ここが通れば「自前で何年もログを蓄積しない例年モノ発見」が現実的になります。通らない場合は Admin Reports API や今後の自前ログ方式を検討します。

## セットアップ

### 1. Apps Script プロジェクトを用意

スタンドアロンの Google Apps Script プロジェクトを作り、このリポジトリの `Code.gs` と `appsscript.json` を配置します。

### 2. Drive Activity API を有効化

`appsscript.json` では `DriveActivity` v2 を高度なGoogleサービスとして宣言済みです。

標準の Google Cloud プロジェクトを紐づけている場合は、Cloud Console 側でも **Drive Activity API** を有効化してください。

### 3. 検索対象フォルダを設定

初期値は `root`（実行ユーザーの My Drive）です。

部署の共有フォルダなど、対象を絞る場合は Apps Script から一度だけ次を実行します。

```javascript
configureSourceFolder('対象フォルダID');
```

元に戻す場合:

```javascript
configureSourceFolder('root');
```

### 4. まず履歴の深さを診断

```javascript
diagnoseHistory();
```

実行ログで、約1年前の編集アクティビティが取得できることを確認します。

### 5. MVPを実行

```javascript
runReinenMono();
```

初回実行時に、Google Drive の **「RE:年モノ」フォルダ** 内へ `RE:年モノ - おすすめ` スプレッドシートを作成します。2回目以降は同じスプレッドシートを更新します。

## 出力項目

- 優先度
- ファイル名
- 昨年同時期の活動日数
- 昨年同時期の EDIT activity 件数
- 直近90日の活動日数
- 昨年の活動開始日
- 昨年の最終活動日
- 今年の目安
- Driveリンク
- File ID

## 現時点の制約

- Drive Activity API が返せる履歴の深さは環境で実測が必要
- 実行ユーザーから見えるアクティビティだけが対象
- `EDIT activity 件数` は厳密なキー入力回数や保存回数ではない
- My Drive の `root` と共有ドライブは同一ではないため、共有フォルダを対象にしたい場合はそのフォルダIDを設定する
- MVPでは「毎年性」の判定は1年前だけ。2年前・3年前の比較は次段階
