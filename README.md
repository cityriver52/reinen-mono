# RE:年モノ

**「去年の今ごろ動いていた仕事」を、今年もそろそろ思い出させるためのツールです。**

Google Drive Activity API の編集アクティビティを使い、担当者個人の閲覧履歴ではなく **ファイルIDを主語** にして、季節性のある業務ファイルを再発見します。

正式表記: **RE:年モノ**  
読み: **レイネンモノ**  
Repository: `reinen-mono`

## UXの考え方

RE:年モノは「スプレッドシートを定期的に見に行くツール」にはしません。

> **普段は存在を忘れていてよく、必要な時だけ静かに思い出させる。**

- 全候補は Google Sheets に保存するが、Sheet は裏側の台帳
- 通常は **週1回、最大3件** だけ Google Chat にプッシュ
- 昨年の開始時期まで22日以上あるものは通知しない
- 昨年の開始時期を過ぎても今年動いていない場合は、**1ファイルにつき今年1回だけ**強めに通知
- 今年ファイルの編集が始まったら、自動的に通知候補から消える
- 通知には「なぜ出たか」を明示する
- `開く / 今年は不要 / あとで` を用意する

詳細は [`docs/UX.md`](docs/UX.md) を参照してください。

## 検出ロジック

実行日を基準に、次の条件を満たすファイルを候補として抽出します。

- 昨年の同日を中心に **±21日** の期間を見る
- その期間に **2日以上** 編集されている、または EDIT activity が **3件以上** ある
- 直近 **90日** は編集されていない
- 担当者ではなくファイルID単位で集計する

出力スプレッドシートは、指定済みの Google Drive フォルダ **「RE:年モノ」** に自動作成します。

## セットアップ

### 1. Apps Script プロジェクトを用意

スタンドアロンの Google Apps Script プロジェクトを作り、このリポジトリの `.gs` ファイルと `appsscript.json` を配置します。

### 2. Drive Activity API を有効化

`appsscript.json` では `DriveActivity` v2 を高度なGoogleサービスとして宣言済みです。

標準の Google Cloud プロジェクトを紐づけている場合は、Cloud Console 側でも **Drive Activity API** を有効化してください。

### 3. 検索対象フォルダを設定

初期値は `root`（実行ユーザーの My Drive）です。

部署の共有フォルダなど、対象を絞る場合は Apps Script から一度だけ次を実行します。

```javascript
configureSourceFolder('対象フォルダID');
```

元に戻す場合:

```javascript
configureSourceFolder('root');
```

### 4. 履歴を診断

```javascript
diagnoseHistory();
```

約1年前の編集アクティビティが取得できることを確認します。

### 5. Google Chat の Incoming Webhook を設定

通知を受けたい Google Chat スペースで Incoming Webhook を作成し、URLを一度だけ保存します。

```javascript
configureChatWebhook('https://chat.googleapis.com/...');
```

疎通確認:

```javascript
sendTestReinenNotification();
```

### 6. フィードバックボタンを使う場合は Web App としてデプロイ

`今年は不要` と `あとで` は `doGet()` で受けます。

Apps Script を Web App としてデプロイしてください。デプロイ後に `ScriptApp.getService().getUrl()` でURLが取得できれば追加設定は不要です。

取得できない環境では明示的に保存できます。

```javascript
configureReinenWebAppUrl('Web App のデプロイURL');
```

Web App を設定していない場合も通知自体は動き、カードには `開く` だけが表示されます。

### 7. 週次通知を設定

デフォルトは月曜9時ごろです。

```javascript
setupWeeklyReinenTrigger();
```

曜日・時間を変える場合:

```javascript
setupWeeklyReinenTrigger('WEDNESDAY', 10);
```

Apps Script の時間主導トリガーなので、指定時刻ちょうどではなく概ねその時間帯に実行されます。

### 8. 手動実行

通知まで含めて手動で試す場合:

```javascript
runWeeklyReinenDigest();
```

Sheetだけ更新したい場合は従来どおり:

```javascript
runReinenMono();
```

## 通知の動作

### 通常の週次通知

昨年の開始目安まで **0〜21日** の候補から、近い順に最大3件を送ります。

### 開始時期超過

昨年の開始目安を過ぎても今年の編集が始まっていない場合、通常ダイジェストとは別に強めの通知を送ります。

同じファイルについては暦年中1回だけです。また1回の実行で最大1件に抑えています。

### 今年は不要

押したファイルはその暦年中、通知対象から外れます。翌年は通常判定へ戻ります。

### あとで

14日間スヌーズします。期間終了後、まだ条件を満たしていれば再び候補になります。

### 自動停止

直近90日に編集が発生すれば、推薦条件から外れるため、ユーザーが「完了」を押す必要はありません。

## スプレッドシート

初回実行時に Google Drive の **「RE:年モノ」フォルダ** 内へ `RE:年モノ - おすすめ` スプレッドシートを作成します。2回目以降は同じスプレッドシートを更新します。

主な出力項目:

- 優先度
- ファイル名
- 昨年同時期の活動日数
- 昨年同時期の EDIT activity 件数
- 直近90日の活動日数
- 昨年の活動開始日
- 昨年の最終活動日
- 今年の目安
- Driveリンク
- File ID

## 現時点の制約

- Drive Activity API が返せる履歴の深さは環境で実測が必要
- 実行ユーザーから見えるアクティビティだけが対象
- `EDIT activity 件数` は厳密なキー入力回数や保存回数ではない
- My Drive の `root` と共有ドライブは同一ではないため、共有フォルダを対象にしたい場合はそのフォルダIDを設定する
- 現時点の「毎年性」判定は1年前だけ。2年前・3年前の比較は次段階
- 検出単位はファイル。複数ファイルを1つの「仕事」に束ねる処理はまだない

## 次にやりたいこと

1. 実運用で通知量と precision を評価
2. 複数ファイルを1つの「例年モノ（仕事）」へクラスタ化
3. 2〜3年分を使った年次性スコアへ拡張
4. 通知後に実際の編集が始まった割合を評価
5. 年間ヒートマップなどの可視化

RE:年モノでは **取りこぼしをゼロにすることより、余計な通知をしないこと** を優先します。
