# RE:年モノ MVP 設計

## 目的

毎年繰り返す仕事を、担当者個人の記憶ではなく Google Drive 上のファイル活動から再発見する。

現在は履歴取得の実環境検証が成功したため、MVPの主眼を次へ進める。

> **役に立つ候補を、ユーザーが一覧を解読しなくても、うるさくない形で適切な時期に提示できるか。**

## データフロー

```text
Google Drive
   │
   │ Drive Activity API / EDIT
   ▼
昨年同時期 ±21日 ──┐
                    ├─ ファイルID単位で集計
直近90日 ──────────┘
                    │
                    ▼
              候補フィルタ
                    │
            ┌───────┴────────┐
            ▼                ▼
      Google Sheets      通知判定
      （裏側の台帳）          │
                             ▼
                     Google Chat
                   （必要時・少量のみ）
```

## なぜ「人」ではなく「ファイル」を主語にするか

人事異動がある組織では、昨年の担当者の個人履歴を今年の担当者へ引き継ぐ設計は壊れやすい。

一方、業務ファイルそのものが残っているなら、File ID をキーにすることで担当者の変更をまたいで季節性を捉えられる。

## 候補判定

### 昨年同時期

実行日の1年前を中心に ±21日。

次のどちらかを満たせば「昨年は活発」とする。

- 2日以上にわたって EDIT activity が存在
- EDIT activity が3件以上

### 最近

直近90日に1日でも EDIT activity があれば推薦から除外する。

「今年すでに仕事が始まっているもの」を出さないことを優先する。

## スコア

```text
score = 昨年の活動日数 × 100
      + min(昨年のEDIT activity件数, 50) × 5
```

説明可能性を優先した暫定スコア。

## Push UX

詳細は `docs/UX.md` を参照。

### まだ早い

昨年の開始目安まで22日以上なら通知しない。

### そろそろ

昨年の開始目安まで0〜21日のファイルを週1回、最大3件だけGoogle Chatへ送る。

### 去年ならもう始まっていた

開始目安を過ぎても今年の編集がない場合、1ファイルにつき暦年1回だけ強めに通知する。

1回の週次実行で最大1件に制限する。

### 自動停止

今年編集が始まり直近90日の休眠条件を外れたら、自動的に推薦から消える。

### 手動抑制

- `今年は不要`: その暦年は通知しない
- `あとで`: 14日間スヌーズ

## Google Chat の技術方式

MVPでは Incoming Webhook を使う。

Webhook は一方向なので、フィードバックはChatの interaction eventには依存しない。カード上のリンクから Apps Script Web App の `doGet()` を開き、Script Properties に抑制状態を保存する。

これにより、本格的なChatアプリ登録・公開をせずにUX仮説を検証する。

## 現在の主要な検証項目

1. 週1回・最大3件で十分に気づけるか
2. 「まだ早い」を黙らせることで通知疲れを防げるか
3. 実際に必要な例年モノが通知上位に来るか
4. `今年は不要` が多発しないか
5. 通知後1〜2週間以内に対象ファイルの編集が始まるか

## MVPでまだやらないこと

- AI / LLMによるファイル本文の理解
- 個人ごとの嗜好学習
- 2年以上を使った周期性判定
- 自動で業務名をクラスタリング
- 本格的な対話型Google Chatアプリ

## 次段階: Seasonal Work

現在はFile ID単位だが、1つの業務に複数ファイルがある場合、複数通知になり得る。

次の大きな改善は、関連ファイルを束ねて通知単位を `Seasonal File` から `Seasonal Work` へ変えること。

## 次段階: Seasonal Frecency

2〜3年前まで取得できる場合は、単純な昨年スコアから周期性スコアへ進化させる。

```text
Seasonality =
    1.0 × 昨年同時期の活動
  + 0.7 × 2年前同時期の活動
  + 0.5 × 3年前同時期の活動

Score = Seasonality
      × 休眠度
      × 年ごとの再現性
```

毎年ほぼ同じ時期に活動が始まるファイルほど「例年モノ度」を高くする。
