# Re:年モノ UX 方針

## 目標

Re:年モノは「一覧を見に行くツール」ではなく、**必要な時だけ静かに思い出させるツール**を目指す。

`Data` は内部台帳であり主UIではない。

## 基本原則

1. Pullさせない。
2. まだ早ければ通知しない。
3. 通常通知は週1回・最大3件。
4. 強い通知も同じファイルへ何度も送らない。
5. ファイル名だけでなく **Driveルートからのフォルダ階層** を見せる。
6. 推薦理由として昨年同時期の活動量と、年度内の他時期に対する季節性倍率を見せる。
7. `今年は不要` と `あとで` で簡単に抑制できる。

## 通知レベル

### まだ早い

昨年の開始目安まで22日以上ある場合は通知しない。

### そろそろ

昨年の開始目安まで0〜21日の候補を週次ダイジェストへ載せる。

- 週1回
- 最大3件
- 開始目安が近い順
- 同日ならスコア順

### 開始時期を過ぎた

開始目安を過ぎた候補は少し強めに通知する。ただし1ファイルにつき暦年1回、1回の実行で最大1件を基本とする。

見出しは `去年なら、もう始まっていました` ではなく、

> 昨年の開始時期から約7日経っています。

のように事実だけを簡潔に表示する。

## 通知カード

Google Chatへはトップレベルの本文 `text` を付けず、**cardsV2のみ**送信する。

カードには以下を表示する。

- ファイル名
- Driveルートからのフォルダ階層
- 昨年同時期の活動日数
- 昨年度の他時期比の季節性倍率
- 開始時期までの日数 / 経過日数

### 開く

Driveの対象ファイルを開く。

### 今年は不要

その暦年は通知対象から外す。状態は `State.skip_this_year` に保存する。

### あとで

デフォルト14日間スヌーズする。状態は `State.snooze_until` に保存する。

### 集計スプシを見る

管理スプレッドシートを開く。ボタン文言は `Dataを見る` ではなく **`集計スプシを見る`** とする。

## State

動的な通知状態はすべてスプレッドシートの `State` で表管理する。

```text
file_id | file_name | year | skip_this_year | snooze_until | overdue_sent_at | updated_at
```

Script Propertiesには保存しない。

## 季節性を前提にした候補判定

単に昨年同時期に使われたことだけでは候補にしない。

比較対象は、その1年前の日付が属する **年度（4月1日〜翌年3月31日）**。その中で「今ごろ±21日」と年度内その他期間を比較し、**その時期だけ利用密度が高かったファイル**を候補にする。

これにより年度を通して毎月使うファイルは基本的に除外する。

直近90日や今年の活動有無による除外は行わない。

## 技術構成

```text
Drive Activity API
        ↓
昨年度（4/1〜翌3/31）のEDIT activity
        ↓
季節ウィンドウ vs 年度内その他期間
        ↓
候補スコアリング
        ├─ Data（再生成）
        └─ State（継続状態）
                ↓
             通知判定
                ↓
        Google Chat Webhook
```

フィードバック操作はApps Script Web App経由で `State` を更新する。
