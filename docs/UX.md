# Re:年モノ UX 方針

## 目標

Re:年モノは「一覧を見に行くツール」ではなく、**必要な時だけ静かに思い出させるツール**を目指す。

`Data` は内部台帳であり主UIではない。

## 基本原則

1. Pullさせない。
2. まだ早ければ通知しない。
3. 通常通知は週1回・最大3件。
4. 強い通知も同じファイルへ何度も送らない。
5. 推薦理由は昨年の活動期間・活動日数で説明する。
6. `今年は不要` と `あとで` で簡単に抑制できる。

## 通知レベル

### まだ早い

昨年の開始目安まで22日以上ある場合は通知しない。

### そろそろ

昨年の開始目安まで0〜21日の候補を週次ダイジェストへ載せる。

- 週1回
- 最大3件
- 開始目安が近い順
- 同日ならスコア順

### 去年ならもう始まっていた

開始目安を過ぎた候補は強めに通知する。ただし1ファイルにつき暦年1回、1回の実行で最大1件を基本とする。

## 通知カード

### 開く

Driveの対象ファイルを開く。

### 今年は不要

その暦年は通知対象から外す。状態は `State.skip_this_year` に保存する。

### あとで

デフォルト14日間スヌーズする。状態は `State.snooze_until` に保存する。

## State

動的な通知状態はすべてスプレッドシートの `State` で表管理する。

```text
file_id | file_name | year | skip_this_year | snooze_until | overdue_sent_at | updated_at
```

Script Propertiesには保存しない。

## 現在の検出前提

候補判定・スコアリングは **昨年同時期の活動だけ** を使う。直近90日や今年の活動有無による除外は行わない。

したがって、現在のMVPでは「今年すでに着手済み」を自動判定して黙るのではなく、必要に応じて `今年は不要` / `あとで` で通知状態を管理する。

## 技術構成

```text
Drive Activity API
        ↓
昨年同時期のactivity
        ↓
候補スコアリング
        ├─ Data（再生成）
        └─ State（継続状態）
                ↓
             通知判定
                ↓
        Google Chat Webhook
```

フィードバック操作はApps Script Web App経由で `State` を更新する。
