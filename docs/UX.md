# RE:年モノ UX 方針

## 目標

RE:年モノは「一覧を見に行くツール」ではなく、**普段は存在を忘れていてよく、必要な時だけ静かに思い出させるツール**を目指す。

スプレッドシートはユーザー向けの主画面ではなく、全候補を保存する裏側の台帳とする。

## 基本原則

1. **Pull させない** — ユーザーに毎週スプレッドシートを見に行かせない。
2. **言わない判断を重視する** — 候補が存在しても、まだ早ければ通知しない。
3. **1回の情報量を絞る** — 通常通知は週1回、最大3件。
4. **同じことを毎日言わない** — 昨年の開始時期を超えた警告も1ファイルにつき今年1回。
5. **今年動き始めたら自動で黙る** — 直近90日に編集があれば推薦候補から外れる。
6. **理由を見せる** — 「なぜ出たのか」を昨年の活動期間・活動日数・最近の休眠で説明する。
7. **ユーザーが簡単に止められる** — 「今年は不要」「あとで」を用意する。

## 通知レベル

### Level 0: まだ早い

昨年の開始目安まで22日以上ある場合は通知しない。

検出結果はスプレッドシートに存在しても、ユーザーには見せない。

### Level 1: そろそろ

昨年の開始目安まで0〜21日になったファイルを、週次ダイジェストに載せる。

- 頻度: 週1回
- 最大: 3件
- 並び順: 開始目安が近い順、同日なら例年モノスコア順
- 表示内容:
  - ファイル名
  - 昨年の活動期間
  - 昨年の活動日数
  - 直近90日は動いていないこと
  - 昨年の開始時期まであと何日か

### Level 2: 去年ならもう始まっていた

昨年の開始目安を過ぎても今年の編集が始まっていない場合、通常ダイジェストとは別に強めの通知を1回だけ送る。

通知疲れを防ぐため、1回の週次実行で送る強通知は最大1件とする。

## 通知カードの操作

### 開く

Google Drive の対象ファイルを直接開く。

### 今年は不要

そのファイルについて、その暦年中はRE:年モノの通知対象から外す。

翌年は再び通常判定に戻る。

### あとで

14日間スヌーズする。

14日経過後、まだ条件を満たしていれば再び通知候補になる。

### もっと見る

全候補を保存している `RE:年モノ - おすすめ` スプレッドシートを開く。

## 自動停止

ユーザーに「完了」を押させない。

対象ファイルに今年の編集活動が発生し、直近90日の休眠条件を満たさなくなれば、自動的に推薦候補から消える。

```text
昨年の開始時期が近づく
        ↓
週次で「そろそろ」
        ↓
今年ファイルが編集される
        ↓
推薦条件から外れる
        ↓
以後は通知しない
```

## 技術構成（MVP）

```text
Drive Activity API
        ↓
例年モノ候補を抽出
        ↓
全候補 → Google Sheets（裏側の台帳）
        ↓
通知判定 / 抑制状態
        ↓
今伝える価値の高いものだけ
        ↓
Google Chat Incoming Webhook
```

フィードバック操作は Google Chat のカードから Apps Script Web App のURLを開き、Script Properties に抑制状態を保存する。

本格的な対話型 Google Chat アプリは、MVPで価値が確認できてから検討する。

## 次段階: ファイルから「仕事」へ

現在の検出単位は File ID。

しかし実際の例年モノは、複数ファイルからなる1つの業務であることが多い。

将来的には、

```text
昨年度通知.docx ─┐
対象者一覧.xlsx ──┤
回答集計.xlsx ────┼→ 「○○調査」という1つの例年モノ
説明資料.pptx ────┤
実施要領.pdf ─────┘
```

のようにクラスタ化し、通知単位を **Seasonal File から Seasonal Work** へ進化させる。

## 成功指標

MVPではクリック率を最大化することより、次を見る。

- 通知を見て「そうそう、そろそろだった」と思える割合
- 「今年は不要」にされる割合
- 通知後1〜2週間以内に対象ファイルの編集が始まる割合
- 通知が多すぎるという不満がないこと

RE:年モノでは recall より precision を優先し、**余計な通知をしないこと自体を品質**として扱う。
